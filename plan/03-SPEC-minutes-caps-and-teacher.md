# SPEC 03 — Minutes, caps, cost, teacher view

**Kiro slug:** `minutes-caps-and-teacher` · Files: `requirements.md`, `design.md`, `tasks.md`
**Why it exists:** Agora bills by the minute. The moment voice is the product, cost becomes a live variable that must be visible, capped and attributable — otherwise "minimal cost for the school" is just a claim.

---

## requirements.md

### Introduction
The backend owns session provisioning records, minute accounting, hard caps, cost attribution for both voice and vision, and a teacher view that shows what each child could not do alone. Nothing here is decorative: with per-minute billing, these are the guardrails that keep the product affordable.

### Requirement 1 — Database schema
**WHEN** the system is deployed **THE SYSTEM SHALL** provide these tables.
**Acceptance criteria**

| Table | Key columns |
|---|---|
| `classes` | id, code, label, created_at |
| `profiles` | id, class_id, nickname, home_lang, target_lang, level, created_at |
| `sessions` | id, profile_id, subject, topic, started_at, ended_at, minutes_used, state |
| `turns` | id, session_id, speaker, text, lang, created_at, flagged |
| `scans` | id, session_id, image_hash, text, items_json, human_verified, created_at |
| `cost_events` | id, kind (`voice`\|`vision`\|`tts`), model, units, cost_php, cached, created_at |
| `caps_daily` | profile_id, day, minutes_used, questions_used, scans_used |

- No table stores a full name, birth date, address, photograph, or any audio.
- Migrations generated by Drizzle and applied on deploy.

### Requirement 2 — Minute accounting
**WHEN** a session runs **THE SYSTEM SHALL** record minutes consumed per session, per learner, per class and per day.
**Acceptance criteria**
- Minutes are the billable unit and the primary meter value.
- `GET /api/minutes?profileId=&classId=` returns `{sessionMin, learnerDayMin, learnerWeekMin, classDayMin, classMonthMin}`.
- Recorded from the session lifecycle, not estimated from client timers.
- A session that ends abnormally still records the minutes consumed.

### Requirement 3 — Hard caps, enforced server-side
**WHEN** a learner reaches a cap **THE SYSTEM SHALL** refuse new billable activity while keeping non-billable content available.
**Acceptance criteria — defaults, configurable by env:**

| Cap | Default |
|---|---|
| Minutes per session | 10 |
| Minutes per learner per week | 30 |
| Scans per session | 3 |
| Sessions per learner per day | 3 |

- Enforced before agent provisioning, never by the client.
- Exceeding a cap returns HTTP 429 with a translated, friendly message and `retryAfter`.
- Cached audio, transcript history and the teacher view remain available when capped.

### Requirement 4 — Cost accounting for voice and vision
**WHEN** any billable unit is consumed **THE SYSTEM SHALL** write a cost event.
**Acceptance criteria**
- Voice: `kind: voice`, `units` = minutes, cost from a per-minute env rate.
- Vision: `kind: vision`, `units` = calls, cost from a per-call env rate; cache hits recorded with `cached: true, cost_php: 0`.
- Rates live in env so the deck can be updated without a redeploy.
- `GET /api/cost` returns session, learner, class and day totals in pesos.

### Requirement 5 — The Minutes Meter
**WHEN** a session is running **THE SYSTEM SHALL** display minutes used against the cap, and the class total for the day.
**Acceptance criteria**
- Visible on the session screen at all times, non-overlapping with controls.
- Shows: minutes this session / cap, minutes this week / cap, and a peso figure for the class today.
- Warning state at 80% of a cap, with an icon plus words (never colour alone).
- Talking point for the demo: it is the honest answer to "what does this cost us?"

### Requirement 6 — Vision-voice interplay
**WHEN** a scan happens mid-session **THE SYSTEM SHALL** attribute the cost separately and never silently extend the session beyond its cap.
**Acceptance criteria**
- Scan cost appears in the meter as its own line.
- A scan never resets or extends the voice-minute cap.
- Cache hits are shown as "₱0" so the saving is visible.

### Requirement 7 — Teacher and parent view (no passwords)
**WHEN** a teacher or parent opens the class code link **THE SYSTEM SHALL** show, per child: what they could not do alone this week, minutes used, and topics covered.
**Acceptance criteria**
- Access by class code only; no accounts, no email.
- No ranking, no comparison, no grades, no leaderboard.
- Nicknames only; printable as one page.
- Parents can see their own child's view only.

### Requirement 8 — Deletion and retention
**WHEN** a deletion is requested **THE SYSTEM SHALL** remove the profile, sessions, turns, scans and cost attribution in one action.
**Acceptance criteria**
- Images are discarded after extraction by default; no retention without an explicit teacher opt-in for a single page.
- No audio of any person is stored, ever.
- Transcripts are retained for 30 days, then purged, unless a teacher opts in.
- Logs contain ids, never names.

### Requirement 9 — Rate limiting and misuse protection
**WHEN** requests arrive faster than a human could produce them **THE SYSTEM SHALL** throttle per profile and per IP.
**Acceptance criteria**
- Per-profile: one session start per 30 s, one question per 3 s, one scan per 5 s.
- Per-IP burst limit protects the Agora balance from being drained accidentally or deliberately.
- Throttled requests are logged and cost nothing.

### Requirement 10 — Operations and health
**WHEN** the app is deployed **THE SYSTEM SHALL** expose operational state for the team.
**Acceptance criteria**
- `GET /api/health` returns build version, active sessions, minutes consumed today, cost today, and provider status.
- API keys, Agora certificates and provider keys exist only server-side; a grep of the client bundle finds none.
- Deploy is a single command on Vercel with Postgres.

### Requirement 11 — Degradation under provider failure
**WHEN** the voice provider is unavailable **THE SYSTEM SHALL** continue in text-only mode with the same tutor prompt and note the mode change in the session log.
**Acceptance criteria**
- Text-only sessions consume no voice minutes.
- The learner is told plainly and in the home language what changed.
- When the provider returns, a new session can be started without losing transcript history.

### Requirement 12 — Honest cost reporting for the submission
**WHEN** the team prepares the deck **THE SYSTEM SHALL** be able to produce a cost statement from real usage.
**Acceptance criteria**
- `GET /api/cost/summary?classId=&from=&to=` returns minutes, scans, pesos, and pesos per learner.
- The statement is generated from recorded events, not from a spreadsheet.
- The number quoted in the pitch matches what the code recorded.

## design.md

### Route list
```
POST /api/tutor/start     provision agent (cap-checked)
POST /api/tutor/llm       our OpenAI-compatible teaching endpoint
POST /api/scan            image → text → session context
POST /api/turn            typed question → session context
POST /api/session/end     close, record minutes, log
GET  /api/minutes         meter
GET  /api/cost            cost totals
GET  /api/cost/summary    submission statement
GET  /api/teacher/[code]  teacher/parent view
POST /api/delete          profile deletion
GET  /api/health          ops state
```

### Cap check order (never invert)
```
1. caps_daily(profile_id, today) → minutes_used, sessions_used, scans_used
2. if any cap exceeded → 429 translated message, no agent provisioned
3. else provision agent, start session, minutes accounted on the server clock
```

### Minute accounting query
```sql
SELECT
  COALESCE(SUM(minutes_used), 0) AS minutes,
  COUNT(*) AS sessions
FROM sessions
WHERE profile_id = $1 AND started_at > now() - interval '7 days';
```

### Cost summary shape
```
{ classId, from, to,
  minutes, scans, voicePhp, visionPhp, totalPhp,
  learners, phpPerLearner, phpPerSchoolYearEstimate }
```

### Env
```
AGORA_APP_ID, AGORA_APP_CERT, AGORA_AGENT_ROLE
LLM_PROVIDER_URL, LLM_API_KEY, LLM_MODEL
ASR_PROVIDER_{LANG}, TTS_PROVIDER_{LANG}, VOICE_{LANG}
RATE_VOICE_PHP_PER_MIN=4.5      # update once real rates are confirmed
RATE_VISION_PHP_PER_CALL=0.30
CAP_MIN_PER_SESSION=10, CAP_MIN_PER_WEEK=30, CAP_SCANS_PER_SESSION=3
DATABASE_URL, BLOB_TOKEN
```
